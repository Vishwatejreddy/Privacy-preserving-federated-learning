# Privacy-Preserving Federated Learning

A PyTorch-based educational simulation of federated learning for the UCI Adult Income dataset. The training records are split across four simulated clients. Each client trains a local neural network, and the server combines client model parameters using Federated Averaging (FedAvg). The example also includes optional Gaussian noise added to model parameters.

## What it demonstrates
- Data preprocessing and feature encoding
- Four simulated federated clients
- Local neural-network training
- Federated Averaging (FedAvg)
- Experimental Gaussian noise injection
- Evaluation on a separate held-out test dataset

## Privacy limitations
This is an educational simulation, **not a formally private or production-secure system**. Gaussian noise injection alone does not prove differential privacy. This code does not calculate an epsilon/delta privacy budget and does not implement secure aggregation or encrypted communication. Describe it as noise-augmented federated learning, not as a formally guaranteed differential-privacy system.

## Dataset
Download the Adult dataset from the UCI Machine Learning Repository:
https://archive.ics.uci.edu/dataset/2/adult

Place `adult.data` and `adult.test` in a local `data/` directory. The dataset is not included in this repository.

Expected layout:
```text
data/
├── adult.data
└── adult.test
```

## Setup
Python 3.10 or 3.11 is recommended.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

## Run
From the repository root:

```bash
python src/federated_learning.py --train-data data/adult.data --test-data data/adult.test
```

Optional parameters:
```bash
python src/federated_learning.py --train-data data/adult.data --test-data data/adult.test --rounds 15 --clients 4 --noise-std 0.002
```

Use `--noise-std 0` for a plain FedAvg baseline.

## Outputs
The script saves `outputs/final_model.pt` and `outputs/accuracy_by_round.png`.

## Reproducibility note
The original report code used machine-specific paths and evaluated using a client data file that was also used for training. This cleaned version instead expects the standard UCI training and test files so the evaluation uses held-out test data. Actual results must be generated by running the code; no accuracy figure is claimed here.
